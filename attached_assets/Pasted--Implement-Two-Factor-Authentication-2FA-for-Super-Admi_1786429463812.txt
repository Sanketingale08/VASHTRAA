# Implement Two-Factor Authentication (2FA) for Super Admin Using Admin Access Key

Implement a secure Two-Factor Authentication (2FA) system for the existing **Super Admin module.

The Super Admin authentication flow must use the existing **Admin Access Key** instead of Login ID + Password.

Important Instructions

* First inspect the existing Super Admin authentication and Admin Access Key implementation.
* Reuse the existing Admin Access Key validation and authentication architecture.
* Do not replace or break the existing Access Key functionality.
* Do not modify Customer or Seller authentication.
* Do not affect unrelated Super Admin functionality.
* Maintain the existing UI design system and responsive behavior.
* Implement production-ready security, validation, error handling, and database persistence.
* Do not use mock OTP/2FA verification.
* Make sure the implementation works in both development and production.

---

# 1. New Super Admin Authentication Flow

The Super Admin login flow should be:

```text
Super Admin Login
       ↓
Enter Admin Access Key
       ↓
Validate Access Key
       ↓
Is 2FA Enabled?
   ↙           ↘
 No             Yes
 ↓               ↓
Dashboard     2FA Verification
                ↓
        Enter 6-Digit Code
                ↓
          Verify 2FA Code
           ↙          ↘
        Valid        Invalid
          ↓             ↓
      Dashboard      Retry / Block
```

The Admin Access Key is the first authentication factor

The Authenticator App code is the second authentication factor

Do NOT add Login ID + Password to this flow unless they already exist as a required part of the current Super Admin authentication system.

---

# 2. Super Admin Access Key Screen

Use the existing Super Admin Access Key screen.

The flow should remain:

### Enter Admin Access Key

```text
Admin Access Key

[ Enter Access Key ]

[ Continue ]
```

Validate the Access Key using the existing backend authentication logic.

If the Access Key is invalid:

**"Invalid Access Key. Please try again."**

Do not expose sensitive authentication information.

If the Access Key is valid, check whether 2FA is enabled for the Super Admin.

---

# 3. If 2FA Is Disabled

If the Super Admin has not enabled 2FA:

```text
Access Key
    ↓
Access Key Valid
    ↓
2FA Disabled
    ↓
Super Admin Dashboard
```

Keep the existing behavior unchanged.

Do not show the 2FA verification screen when 2FA is disabled.

---

# 4. If 2FA Is Enabled

If 2FA is enabled:

```text
Access Key
    ↓
Access Key Valid
    ↓
2FA Enabled
    ↓
2FA Verification Screen
```

The Super Admin must NOT receive full dashboard access immediately after Access Key validation.

Create a temporary/pre-authentication state until 2FA is successfully verified.

# 5. 2FA Verification Screen

Display:

### Verify Your Identity

"Enter the 6-digit code from your authenticator app."

OTP input:

```text
[ _ ][ _ ][ _ ][ _ ][ _ ][ _ ]
```

Buttons:

**Verify Code**

and:

**Use Recovery Code**

The Super Admin must enter the current TOTP code generated by their authenticator application.

---

# 6. Successful 2FA Verification

If the 6-digit code is valid:

```text
Access Key
    ↓
Valid
    ↓
2FA Code
    ↓
Valid
    ↓
Create Authenticated Super Admin Session
    ↓
Super Admin Dashboard
```

Only after successful 2FA verification should the application create/upgrade the fully authenticated Super Admin session.

Regenerate the session identifier where appropriate.

---

# 7. Failed 2FA Verification

If the OTP is invalid:

Display:

**"Invalid verification code. Please try again."**

Allow the Super Admin to retry.

Implement rate limiting and protection against repeated brute-force attempts.

Do not reveal whether the code was close to being correct.

# 8. Use Recovery Code

Add:

**Use a recovery code instead**

When selected:

```text
2FA Verification
       ↓
Use Recovery Code
       ↓
Enter Recovery Code
       ↓
Validate Code
       ↓
Valid?
 ↙        ↘
Yes       No
 ↓         ↓
Login    Error
```

If the recovery code is valid:

* Authenticate the Super Admin.
* Mark the recovery code as permanently used.
* Create the authenticated Super Admin session.
* Redirect to the dashboard.

Display:

**"Recovery code accepted. This code can no longer be used."**

```text

    ↓
Validate Access Key
    ↓
Generate TOTP Secret
    ↓
Display QR Code
    ↓

    ↓
Enter 6-Digit Code
    ↓
Verify Code
    ↓
Enable 2FA
```

Do not use Login ID + Password for this flow unless required by the existing authentication architecture.

# 12. Verify and Activate 2FA

After scanning the QR code:

Ask the Super Admin to enter the current 6-digit authenticator code.

If valid:

* Enable 2FA.
* Store the 2FA configuration securely.
* Generate recovery codes.
* Show the recovery codes once.

If invalid:

**"Invalid verification code. Please try again."**

2FA must not be marked as enabled until the first authenticator code is successfully verified.

---

# 13. Recovery Codes

Generate **8–10 unique recovery codes**.

Display:

### Save Your Recovery Codes

"Keep these recovery codes in a secure place. Each code can only be used once."

Provide:

* Copy Codes
* Download Codes
* Continue

Security requirements:

* Generate codes securely.
* Store hashes instead of plain-text codes where possible.
* Each code can only be used once.
* Used codes must be invalidated permanently.
* Do not display the complete codes again after leaving the setup screen.

When 2FA is enabled:

**Settings → Security & Access → Two-Factor Authentication → Manage 2FA**

Provide:

* 2FA Status
* Regenerate Recovery Codes
* Disable 2FA

To disable:

```text
Disable 2FA
     ↓
Enter Admin Access Key
     ↓
Verify Authenticator Code
     ↓
Confirmation
     ↓
Disable 2FA
```

Show confirmation:

### Disable Two-Factor Authentication?

"Disabling two-factor authentication will reduce the security of your administrator account."

Buttons:

**Cancel | Disable 2FA**

After successful verification:

* Disable 2FA.
* Invalidate the TOTP secret.
* Invalidate all recovery codes.
* Update the database.
* Add an Audit Log entry.

# 15. Regenerate Recovery Codes

When the Super Admin selects **Regenerate Recovery Codes**:

Require:

1. Valid Admin Access Key
2. Current Authenticator Code

Then:

* Invalidate all previous recovery codes.
* Generate new recovery codes.
* Store them securely.
* Display them once.
* Allow Copy / Download.

Show warning:

**"Generating new recovery codes will invalidate all previously generated recovery codes."**

# 17. Authentication State

Implement three authentication states:

### State 1 — Unauthenticated

```text
No Access Key
```

Cannot access Super Admin routes.

### State 2 — Access Key Verified / 2FA Pending

```text
Access Key Valid
2FA Not Yet Verified
```

Allow access ONLY to the 2FA verification flow.

Do NOT allow:

* Dashboard
* Settings
* Seller Management
* Customer Management
* Reports
* Audit Logs
* Other protected Super Admin modules

### State 3 — Fully Authenticated

```text
Access Key Valid
+
2FA Valid
```

Allow full Super Admin access.

# 18. Security Requirements

### Admin Access Key

* Reuse the existing secure Access Key validation.
* Never expose the Access Key in frontend code.
* Never log the Access Key.
* Rate-limit failed Access Key attempts.

### TOTP

* Use a standard TOTP implementation.
* Generate secure random secrets.
* Do not store secrets in plain text if the existing architecture supports secure encryption.
* Never log OTP values.

### Brute Force Protection

Protect both:

* Admin Access Key verification
* 2FA verification

Implement:

* Failed-attempt tracking
* Rate limiting
* Temporary lockout after repeated failures

### Session Security

Before 2FA verification:

**Do not create a fully authenticated Super Admin session.**

After successful 2FA verification:

* Create/upgrade the authenticated session.
* Regenerate session identifiers where appropriate.
* Apply the existing session timeout.
* Preserve existing logout behavior.
