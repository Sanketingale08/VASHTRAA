TwirlDrape Refactoring Specification
IMPORTANT
•	The User Portal, Seller Portal, and Admin Panel are ALREADY IMPLEMENTED.
•	Do NOT rebuild the application from scratch.
•	Do NOT redesign the current UI unless necessary.
•	Do NOT remove any existing functionality.
•	Only refactor the routing, authentication, authorization, and portal separation.
PROJECT GOAL
The existing User Portal is the Customer Portal.
•	There should only be three roles: User (Customer), Seller, Super Admin.
•	Customer Portal = User Portal.
•	Do NOT create another Customer Portal.
•	Treat the existing User Portal as the Customer Portal.
PORTALS
•	User Portal (Customer Portal)
•	Seller Portal
•	Super Admin Portal
•	Each portal must have independent authentication, layouts, navigation, protected routes, and permissions.
•	Users from one portal must NEVER access another portal.
ROLE BASED ACCESS CONTROL (RBAC)
•	Roles: customer, seller, admin.
•	Each authenticated account has one role only.
•	Create middleware: isAuthenticated, isCustomer, isSeller, isAdmin.
•	Redirect unauthorized users to /unauthorized.
ROUTING
•	User (Customer): /customer/* or keep existing /user/* routes.
•	Seller: /seller/*
•	Admin: /admin/*
•	Map User = Customer.
•	Do not duplicate the customer portal.
AUTHENTICATION
•	User Login: /login or /customer/login (existing route).
•	User Register: /register.
•	Seller Login: /seller/login.
•	Seller Register: /seller/register.
•	Admin Login: /admin/login.
•	Seller Dashboard: /seller/dashboard.
•	Admin Dashboard: /admin/dashboard.
USER (CUSTOMER) PORTAL
•	Keep the current shopping website exactly as it is.
•	Do NOT redesign or change functionality.
•	Only fix routing and permissions.
•	Remove Seller Panel, Seller Dashboard, Seller Menu, Seller Links, Seller Navigation, Seller Buttons, Seller Routes, and Seller Profile Links.
•	Customers must never see Seller-related menus.
User Features:
•	Browse Products
•	Search Products
•	Categories
•	Filters
•	Wishlist
•	Cart
•	Checkout
•	Payment
•	Order History
•	Order Tracking
•	Return Request
•	Cancel Order
•	Reviews
•	Ratings
•	Profile
•	Saved Addresses
•	Notifications
SELLER PORTAL
•	Keep the existing Seller Portal.
•	Do NOT redesign or change Seller functionality.
•	Ensure seller routes are isolated.
•	Customer Header, Navigation, and Components must never appear.
•	Seller URL: /seller/login
•	Dashboard: /seller/dashboard
SUPER ADMIN PORTAL
•	Keep the existing Admin Portal.
•	Do NOT redesign or change Admin functionality.
•	Ensure admin routes are isolated.
•	Admin URL: /admin/login
•	Dashboard: /admin/dashboard

FINAL REQUIREMENTS
•	Do NOT rebuild existing pages.
•	Do NOT redesign the User (Customer) website.
•	Keep all existing shopping functionality.
•	Only remove Seller access from the User Portal.
•	Seller functionality must only exist inside the Seller Portal.
•	Admin functionality must only exist inside the Admin Portal.
•	Refactor routing using proper RBAC.
•	Protect every route using middleware.
•	Hide Seller routes and navigation from Users.
•	Hide Admin routes from Users and Sellers.
•	Hide Sellers routes 
•	Preserve existing functionality.
•	Generate production-ready, scalable architecture with reusable components.
